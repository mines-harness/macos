# Mines device service

This service stores account membership and device public keys. It forwards short-lived signed WebRTC descriptions and optional generic push alerts. By default, conversations, catalog metadata, resources, and provider credentials travel over the approved direct device connection. An explicit guest-sharing option below allows guest HTTP traffic and live streams to traverse control; it does not change device connection policy.

Accounts are self-hosted with Better Auth and Postgres. Configure `MINES_AUTH_URL` (the public HTTPS origin), `MINES_AUTH_SECRET` (at least 32 random characters), `MINES_ALLOWED_ORIGINS` (comma-separated client origins, including `mines://app` for the desktop app), and `DATABASE_URL`. Run `node infra/mines-control/src/main.ts` from the installed workspace. The process listens on loopback port 8788 by default; publish it behind HTTPS with the example Caddy configuration. Authentication tables migrate at startup. The public root page supports account creation, sign-in, and recovery. Do not enable access logs containing query strings: signaling connections and account emails contain short-lived credentials.

Configure `MINES_SMTP_HOST`, `MINES_SMTP_PORT`, and `MINES_SMTP_FROM`, with optional `MINES_SMTP_USER` and `MINES_SMTP_PASSWORD`, to send verification and password-reset emails through your own mail server. Email verification is required when SMTP is configured. Password recovery remains unavailable without SMTP. External SMTP requires TLS; a local mail service may accept unencrypted loopback connections. Password resets revoke existing account sessions.

Clients use `/api/auth/sign-up/email`, `/api/auth/sign-in/email`, `/api/auth/get-session`, and `/api/auth/sign-out`. Store the signed `set-auth-token` response header and send it as an Authorization bearer token; the unsigned JSON token is not accepted. Browser clients omit cookies for these requests. The reverse proxy must overwrite `X-Real-IP` with the actual client address because authentication rate limits use that header. Keep the service listener on loopback so clients cannot forge the trusted proxy header directly.

`compose.yaml` prepares a small single-instance deployment with Postgres and a STUN-only coturn service. Set `MINES_CONTROL_IMAGE` to a built workspace image and provide the required environment variables. Review and pin deployment images to registry digests before publishing. Only HTTPS and UDP 3478 need public ingress. No TURN ports, relay allocation, or managed tunnel is configured. Application proxying stays disabled unless guest sharing is explicitly enabled. Device tickets and live presence are memory-local; run one control instance until presence coordination is deliberately added. Postgres needs encrypted backups and private networking.

The host must approve a device's key separately from account registration. Signed descriptions bind the approved identity to the DTLS certificate fingerprint; the signaling service cannot substitute a new transport certificate. Revoking account membership stops new signaling; revoke the device on the host as well to terminate established sessions. Protect the host's persisted identity as a credential.

Direct connectivity can fail on restrictive mobile or corporate networks and symmetric NAT. A failure must offer retry, another network, and cached history. It must never silently fall back to a relay. A sleeping or offline host cannot serve live history. Measure connection attempts and outcomes locally; export only opt-in aggregate counts by coarse failure category, without IPs, SDP, device identifiers, or chat content.

## Optional public guest sharing

Set `MINES_GUEST_PUBLIC_URL=https://mines.gemstud.io` on control to advertise that HTTPS origin through public `GET /v1/guest-config` and enable the guest proxy. The value must be an origin, with no credentials, path, query, or fragment. Leave it unset for the direct-only default. It does not enable `MINES_RELAY_URL`, TURN, or account/device application relaying.

Publish the built `apps/web` application on that origin with `/guest` falling back to its `index.html`. The commented Caddy site block serves that build and routes `/v1/guest-config` and `/api/guest/*` to control. Point DNS at your server and allow Caddy to obtain HTTPS certificates. Keep `flush_interval -1` on the guest proxy so server-sent events reach browsers immediately. The ordinary control domain also carries the host's outbound WSS connection; no host port forwarding or inbound NAT rule is needed. Do not put an account login in front of the guest site or its guest API. Guest links use `/guest?host=<deviceId>#<credential>`; the fragment credential is redeemed by the guest client, never sent in the page URL's HTTP request.

The host must already be registered with this control service and explicitly enable its guest forwarder. It obtains an existing signed-device ticket and connects to `/v1/guest-host?ticket=<ticket>`. Tickets remain single-use and expire after 30 seconds. The control service derives the route ID from the authenticated device identity; account revocation closes that connection. Guest admission, nickname/session credentials, permissions, expiry, rate limits, and files remain authoritative on the host. Control holds no conversation database or offline delivery queue, but it can observe guest traffic in transit. Restrict access to control and do not log ticket query strings, guest cookies, request bodies, or stream contents.

Only POST `redeem`/`messages` and GET `session`/`stream`/`item`/`command-output`/`render`/`attachment` under `/api/guest/hosts/<deviceId>/` are forwarded to host guest routes. Owner APIs, HEAD, redirects, account cookies, and arbitrary destination URLs are excluded. Only `mines_guest_*` cookies pass; response cookie paths are scoped to that host route, Domain is removed, and the host's dynamic expiry is retained. Guest responses enforce `nosniff` and a sandbox CSP so hosted files cannot execute with the public site's origin.

Guest IP attribution uses the TCP socket address by default and ignores forwarded headers. Behind Caddy, set `MINES_GUEST_TRUSTED_PROXIES` to a comma-separated list of **exact immediate proxy IP addresses** and retain `header_up X-Real-IP {remote_host}`. IPv4-mapped IPv6 addresses are normalized. CIDRs, wildcards, forwarded chains, and arbitrary `X-Forwarded-For` are not accepted. A trusted proxy with a missing or invalid `X-Real-IP` is rejected. With Compose port publishing, the immediate source seen inside the container can be the Docker bridge gateway rather than `127.0.0.1`; verify that address in your deployment and configure only that address. Keep port 8788 private and ensure every process able to reach it from a trusted address is trusted to overwrite that header. An upstream CDN needs a deliberate trusted-client-IP configuration at Caddy; blindly forwarding its client headers is unsafe and otherwise attributes guests to the CDN's source IP.

The proxy caps each host at 256 pending HTTP requests, globally at 1,024, with a 10 MiB + 64 KiB body limit and 32 MiB aggregate body buffering. Response chunks are at most 48 KiB, and each request sends its next chunk only after control acknowledges the previous response write/drain. Incoming host response frames are limited to 96 KiB; larger request bodies travel in the opposite direction. Queued requests toward hosts are bounded to 16 MiB per connection and 32 MiB globally; a host bounds its outgoing response queue to 24 MiB. HTTP disconnects cancel host work, host disconnect/replacement fails active requests, and an unanswered response head expires on the control heartbeat. Streams are live only while the host is awake and connected. These limits may require a dedicated control instance for larger deployments.

## Generic phone notifications

Set `MINES_EXPO_PUSH_ACCESS_TOKEN` only on the control service, from your own Expo account with enhanced push security enabled. Configure the mines EAS project (`MINES_EAS_PROJECT_ID`) and its APNs/FCM credentials, then build mobile with `MINES_CONTROL_URL`. Enable `MINES_PUSH_ENABLED=1` on a host already registered with that device service (for a boot service, put it in `<MINES_HOME>/service.env` and restart). On the phone, sign in and enable Agent updates in Notifications settings. No upstream T3 relay or push credentials are used. The capability stays disabled when the control service token is missing; APNs/FCM provisioning and an installed native build are still required for delivery.

The service accepts only signed fixed event kinds and random opaque IDs. It rejects extra fields such as chat titles, text, and thread IDs, and constructs the visible generic notification itself. Tokens register with account authentication plus the existing device key; only active devices in the same account receive events. Account/device limits bound requests, the host queue holds at most 64 generic events, and event IDs expire after one day. Push tokens expire after 90 days without registration refresh. Revoked devices cannot receive new alerts; explicit opt-out removes the token. Phones persist a pending removal when offline and retry it on the next session; revoking the device from another signed-in client stops alerts immediately at the service.

`accepted` means Expo accepted the request, never that a phone displayed it. The implementation drops notification failures rather than blocking agent execution and does not replay missed host events after a restart. No notification provider credentials are configured or deployed by this repository. Expo forwards these generic payloads to your configured APNs/FCM services; see [Expo push setup](https://docs.expo.dev/push-notifications/push-notifications-setup/) and [push security](https://docs.expo.dev/push-notifications/sending-notifications/#additional-security).
